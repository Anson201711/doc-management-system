## 1. 系统架构概述

### 1.1 架构设计原则
- **高可用**：系统具备容错能力，确保服务持续可用
- **可扩展**：支持水平扩展，满足业务增长需求
- **松耦合**：模块间低耦合，便于维护和升级
- **安全性**：多层次安全防护，保障数据安全

### 1.2 系统分层架构

```
┌─────────────────────────────────────────────────────┐
│                    表现层 (Presentation)              │
│  Web端  |  移动端  |  API网关  |  第三方集成          │
├─────────────────────────────────────────────────────┤
│                    业务层 (Business)                 │
│  文档管理  |  版本控制  |  权限管理  |  协作  |  工作流 │
├─────────────────────────────────────────────────────┤
│                    服务层 (Service)                   │
│  用户服务  |  文件服务  |  通知服务  |  搜索服务       │
├─────────────────────────────────────────────────────┤
│                    数据层 (Data)                      │
│  关系型数据库  |  对象存储  |  缓存  |  搜索引擎       │
└─────────────────────────────────────────────────────┘
```

## 2. 核心模块设计

### 2.1 文档管理模块

#### 功能职责
- 负责文档的创建、存储、检索、分类、标签管理
- 支持多种文件格式的预览和下载

#### 关键组件
| 组件 | 职责 |
|------|------|
| DocumentService | 文档业务逻辑处理 |
| FileProcessor | 文件处理（转换、压缩） |
| MetadataManager | 元数据管理 |
| CategoryService | 分类目录管理 |
| TagService | 标签管理 |
| SearchService | 全文搜索服务 |

#### 数据模型
```
Document {
  id: String (主键)
  title: String
  file_key: String (对象存储路径)
  category_id: String
  tags: String[]
  owner_id: String
  created_at: DateTime
  updated_at: DateTime
  status: Enum (草稿/已发布/已归档)
  version: Integer
}
```

### 2.3 权限管理模块

#### 功能职责
- 基于RBAC的访问控制
- 文档级别的细粒度权限管理

#### 权限模型
```
Role {
  id: String
  name: String (管理员/部门负责人/普通用户)
  permissions: Permission[]
}

Permission {
  resource: String (文档/文件夹)
  action: String (查看/编辑/删除/分享/管理)
  scope: String (本人/本部门/全部)
}
```

#### 权限决策流程
1. 检查用户角色权限
2. 检查文档所有者权限
3. 检查文档ACL（访问控制列表）
4. 继承父文件夹权限
5. 返回最终决策

## 5. 业务规则定义

| 规则编号 | 规则名称 | 规则描述 | 约束范围 |
|----------|----------|----------|----------|
| DR-001 | 文件类型限制 | 支持Word/Excel/PPT/PDF/图片/文本等常见格式 | 上传文件校验 |
| DR-002 | 文件大小限制 | 单个文件默认最大100MB | 上传文件校验 |
| DR-003 | 文件名规范 | 文件名最长200字符，禁止字符 /:*?"<> | 文件名校验 |
| DR-004 | 分类层级限制 | 分类目录最多支持5级层级 | 分类创建/编辑 |
| DR-005 | 标签数量限制 | 单个文档最多10个标签 | 标签添加 |
| DR-006 | 文档标题唯一性 | 同一分类下文档标题必须唯一 | 文档创建/重命名 |

#### 6.2.3 搜索功能

```
                          ┌─────────────────┐
                          │   负载均衡 (LB)  │
                          └────────┬────────┘
                                   │
          ┌────────────────────────┼────────────────────────┐
          │                        │                        │
    ┌─────▼─────┐            ┌─────▼─────┐            ┌─────▼─────┐
    │  应用节点1 │            │  应用节点2 │            │  应用节点3 │
    │ (Web/API) │            │ (Web/API) │            │  索引消费者│
    └─────┬─────┘            └─────┬─────┘            └─────┬─────┘
          │                        │                        │
          └────────────────────────┼────────────────────────┘
                                   │
          ┌────────────────────────┼────────────────────────┐
          │                        │                        │
    ┌─────▼─────┐            ┌─────▼─────┐            ┌─────▼─────┐
    │ PostgreSQL │            │   Redis   │            │Elasticsearch│
    │  (主从)   │            │  (集群)   │            │  (集群)   │
    └───────────┘            └───────────┘            └───────────┘
                                   │
                          ┌────────┴────────┐
                          │   RabbitMQ      │
                          │  (消息队列)     │
                          └─────────────────┘
                                   │
                          ┌────────┴────────┐
                          │   对象存储      │
                          │   (MinIO/OSS)  │
                          └─────────────────┘
```

**数据流说明：**
- 文档操作 → 应用节点 → 消息队列(RabbitMQ) → 索引消费者 → Elasticsearch
- 搜索请求 → 应用节点 → Elasticsearch → 返回结果
